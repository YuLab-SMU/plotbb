# plotbb 0.5.0 decisions

0.5.0 delivers `bb_build()` and `bb_save()`. Four items from the roadmap were
kept as decisions rather than implementations; this note records the decisions
so later work does not re-open them from memory.

## Per-layer legend

**Decision**: not implemented. The legend continues to describe the plot-level
mapping, not individual layers.

**Why**: a per-layer legend needs a rule for ownership (which layer a legend
belongs to), count (one per aesthetic? per layer?), placement (inside/outside,
multiple legends in one figure) and interaction with a layer's local mapping
and scale. Those are semantic choices, not implementation details; adding them
now would create a second, half-specified legend system next to the plot-level
one.

**When to revisit**: when a real workflow cannot be expressed with the
plot-level legend. Start with a decision record covering ownership, count,
placement and the mapping/scale of a layer legend, then implement.

## Free colour scales by facet

**Decision**: keep one shared colour domain for all panels. Per-panel colour
scales are not supported.

**Why**: a shared domain is what makes panels comparable, and it matches the
0.3.0 training rule (train once on the full plot). A per-panel colour scale
immediately raises the legend question: one legend cannot describe different
domains, and per-panel legends multiply the layout problem above.

**When to revisit**: after the facet layout tail (long labels, empty levels,
free scale combinations) and after the per-layer legend decision, since both
need the same legend layout work. Keep the shared domain as the default even
then.

## bb_facet_grid()

**Decision**: deferred until the facet layout tail is finished.

**Why**: a grid facet needs a row/column variable model and the same empty
cell / free scale / label rules as `bb_facet_wrap()`; adding it before those
rules are settled would duplicate them.

## Multi-plot layout

**Decision**: not implemented in plotbb. Multiple complete plots are composed with
`aplot::plot_list()` from the same author's aplot package; aplot has no
`plot_grid()`.

**Why**: `+` means "add a layer/component to one plot"; arranging complete plots
is a different operation with its own device and layout state. Implementing a
second layout system next to aplot would duplicate it and split the semantics.
The boundary is already enforced by `+.bbplot`, which errors when given a second
complete plot and points at `aplot::plot_list()`.

**Not the same as facets**: `bb_facet_wrap()` and `bb_facet_grid()` lay out
panels inside one plot and remain plotbb's responsibility.

## Colour bar polish

**Decision**: deferred (low priority). Minor ticks, a gradient legend for
discrete scales and long-title wrapping are cosmetic additions to the current
colour bar; they do not change the scale semantics and can be added without a
new decision.

## Not implemented in 0.5.0

`bb_violin()`, `bb_smooth()`, per-layer legend, free colour scales by facet,
`bb_facet_grid()` and the colour-bar polish stay on the 0.5.0+ backlog, with the
trigger conditions recorded in the roadmap.
