# plotbb 0.3.0 scale and legend design decisions

This note records the API decisions behind 0.3.0 ("尺度和图例语义统一"). It is
the reference for the code, the tests and the vignette section.

## 1. One scale object per aesthetic

A scale is stored under the aesthetic it governs (`plot$scales[[aesthetic]]`).
`col` and `fill` are separate aesthetics with separate scales; `pch`, `lty` and
`cex` follow the same shape.

* `bb_scale_col_*()` keeps its signature and creates a `col` scale.
* `bb_scale_fill_palette/manual/gradient()` are the new `fill` counterparts.
* `bb_scale_pch/lty/cex_*()` are unchanged apart from the shared fields below.

A scale carries: `aesthetic`, `type` (`manual`/`palette`/`gradient`/
`continuous`/`range`), `palette` (colour) or `values` (symbol), `limits`,
`domain`, `breaks`, `labels`, `na.value`, `oob`, `drop`.

### Compatibility

The old constructors keep their signatures and classes. `bb_scale_col_*()`
still applies to `col`. A `fill` mapping without a fill scale now uses the
default fill mapping instead of silently borrowing the `col` scale; the
migration is a single line (`bb_scale_fill_*()`), stated in NEWS.

## 2. Training

`bb_train_scales(plot)` runs at draw time, once per plot, from:

* the plot-level mapping evaluated on the plot data;
* every layer's effective mapping (inherited minus constant aesthetics),
  evaluated on that layer's own data when it has one.

Rules:

* **discrete**: factor levels first (in factor order), then character values in
  first-appearance order; numeric values of a manual scale keep appearance
  order. `drop = TRUE` (default) keeps only observed levels; `drop = FALSE`
  keeps all factor levels.
* **continuous**: the finite range of all trained values. A zero-width range is
  widened by ±0.5 so interpolation is defined.
* **limits** override the trained domain. For a discrete scale they also define
  which levels appear; data values outside `limits` map to `na.value`.
* **all missing**: `domain` stays `NULL` and every value maps to `na.value`;
  nothing is computed from `Inf`/`NaN`.
* **facets** share one domain: training happens on the full plot before the
  panel loop, and each panel inherits the trained scales.

## 3. Mapping

`bb_map_aesthetic(plot, aesthetic, values)` is the only place a value becomes
ink. Layers (and the legend) call it; no layer derives its own colour rule.

* discrete: named `values`/`palette` match by level name; unnamed values match
  by level position in the trained domain. An unmatched level or `NA` yields
  `na.value` — never a recycled colour.
* continuous: `scales::col_numeric()` with the same palette and domain as the
  legend. `oob = "squish"` (default) clamps values outside `limits`;
  `oob = "censor"` maps them to `na.value`.
* pch/lty/cex: the same discrete/continuous split, with defaults when no scale
  is given. A mapped `lty` is applied by the line-like layers (`bb_line()`,
  `bb_segment()`, `bb_errorbar()`, `bb_lm()`, `bb_boxplot()`); a polyline uses
  the first value per line, a segment or error bar one per row, a box one per
  box (in box order), and a fitted line one per group.

## 4. Legends

`bb_draw_legend()` reads the trained scale and the mapped values and draws:

* a discrete legend through `graphics::legend()`: `fill` uses filled boxes,
  `col` uses points, `pch`/`lty`/`cex` use their own symbols;
* a colour bar for continuous colour scales, with the scale palette, domain,
  `breaks` (default `pretty()`), `labels` and `orientation`
  (`"vertical"` default, `"horizontal"` available);
* outside legends in a dedicated layout column, for both discrete and
  continuous scales, so they do not cover the panel.

`bb_legend()` gains `orientation` (colour bars) and keeps `position`, `title`,
`pch`, `bty`, `outside` and `...`.

## 5. Known limits of this release

* One domain per aesthetic per plot: free colour scales by facet are not
  supported (facets share the global domain, as the roadmap suggests).
* Colour bar ticks use base `pretty()` unless `breaks` is given; no minor
  breaks, no gradient legend for discrete scales.
* `fill` is still only an aesthetic for layers that have an interior
  (`bb_tile()`, `bb_density()`, `bb_bar()`, `bb_boxplot()`, `bb_hist()` and the
  confidence band of `bb_lm()`); other layers reject it as in 0.2.5.
* A per-layer legend is not part of this release: the legend still describes
  the plot-level mapping.
